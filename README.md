# Nissan Leaf Diag — Android MVP

Застосунок для Android, який підключається до ELM327 по Bluetooth Classic (SPP) і читає Nissan Leaf AZE0-подібні CAN дані.

## Що вже реалізовано

- пошук спарених Bluetooth Classic ELM327;
- RFCOMM/SPP підключення;
- ініціалізація ELM327 для ISO 15765-4 CAN 11-bit / 500 kbit/s;
- читання:
  - SOH через CAN ID 0x5B3;
  - GIDs та оцінки збереженої енергії;
  - одометра через 0x5C5;
  - SOC через EV-CAN запит `79B -> 7BB`, `21 01`;
- базовий CAN monitor;
- журнал сирих відповідей;
- сканер ідентифікації ECU для Leaf ZE0/AZE0;
- для VCM, BCM, ABS/VDC, LBC/BMS, inverter, meter, HVAC, EPS, TCU, IPDM, airbag, charger та інших модулів виконується опитування;
- читаються UDS-подібні ідентифікаційні DID:
  - F1A0 — diagnostic/version information;
  - F18A — supplier/manufacturer;
  - F194 — software number;
  - F195 — software version;
  - F190 — VIN, якщо ECU його надає.

## Важливо про Nissan Leaf

Leaf має три CAN-шини: Car-CAN, EV-CAN і AV-CAN. Стандартний OBD роз'єм дає доступ до різних шин на різних контактах; звичайний ELM327 через стандартний роз'єм працює насамперед з Car-CAN, а доступ до EV-CAN залежить від адаптера/розводки та підтримки команд ELM327.

Цей MVP орієнтований на Leaf AZE0 (2011–2017), включно з 2016 модельним роком. Для ZE1/інших ревізій декодери треба винести в окремі профілі.

## Що треба доробити для повноцінного аналога LeafSpy

1. BLE-підтримка для адаптерів типу LE Link / LELink.
2. ISO-TP multi-frame парсер без залежності від поведінки конкретного ELM327.
3. Профіль Leaf AZE0:
   - 96 пар комірок;
   - 3–4 температурні датчики;
   - pack voltage/current;
   - Ah;
   - Hx;
   - charge counters;
   - VIN;
   - зарядний стан;
   - інвертор/мотор.
4. Розширити профілі ECU і UDS/OBD запити для:
   - VCM;
   - LBC;
   - inverter/motor;
   - charger;
   - HVAC;
   - ABS/VDC;
   - EPS;
   - BCM та інших ECU.

   Базова карта request/response ID для ZE0/AZE0 вже внесена в `EcuScanner.kt`. Вона походить із відкритої документації Leaf CAN: VCM 0x797→0x79A, BCM 0x745→0x765, ABS 0x740→0x760, LBC 0x79B→0x7BB, inverter 0x784→0x78C тощо.
5. Читання та безпечне стирання DTC з підтвердженням користувача.
6. Запис логів у CSV/SQLite та графіки.
7. Автоматичне визначення AZE0/ZE1 і регіону.
8. Захист від випадкових команд запису.

## Збірка

Відкрийте папку в Android Studio та виконайте Gradle Sync → Run.

Потрібен Android SDK 35.

## Безпека

Під час першого тесту використовуйте якісний ELM327. Не надсилайте команди запису/кодування ECU, доки вони не перевірені для конкретного Leaf. Дешеві або несправні адаптери можуть некоректно працювати на CAN-шині.

## Ідентифікація ECU

Функція «Зчитати моделі та прошивки ECU» опитує блоки по їхніх діагностичних CAN ID та намагається отримати ідентифікаційні дані. Це **читання**, без команд запису/перепрошивки.

Не кожен ECU Leaf повертає всі DID, тому `—` означає відсутність відповіді або непідтримуваний DID, а не несправність блока. Для максимальної сумісності з конкретним ECU потрібні його точні діагностичні послідовності та ISO-TP обробка multi-frame.

## ELM327 Test

У застосунку додано кнопку `ELM327 Test`. Вона перевіряє:

- `ATI` — ідентифікатор/версію ELM327;
- `AT@1` — опис адаптера;
- `ATSP?` — поточний протокол;
- `ATDP` — текстовий опис протоколу;
- `ATE0`, `ATL0`, `ATH1`, `ATS1`, `ATAL` — базові можливості AT-команд;
- `ATSP6` — вибір ISO 15765-4 CAN 11-bit / 500 kbit/s;
- `0100` — функціональний тест відповіді OBD/CAN.

Результати виводяться в журнал із позначеннями `✓`/`✗`. Жодна команда тесту не виконує запису або перепрограмування ECU.

> Для клона ELM327 текст `V1.5` на корпусі не є доказом реальної версії прошивки. `ATI` є фактичним тестом відповіді адаптера.
